# StaySpot — User Descriptions

## 1. Guest

A guest uses StaySpot to explore vacation rental properties, check property details and amenities, and make a booking.

**User needs:**
- Browse and search available properties.
- View property details and amenities.
- Book a property and receive clear success or failure feedback.
- Check wallet balance and transaction history.

## 2. Property Manager / Platform Operator

A property manager or platform operator uses StaySpot to inspect bookings and properties and understand property performance.

**User needs:**
- Browse guests, properties and bookings.
- Search and filter records.
- View booking details and status.
- Review wallet audit history.
- Compare property revenue and performance rankings.
- Explore search hotspots and property review analytics.

## 3. Design Assumptions

- The application is a demonstration interface built on the inherited StaySpot database.
- Real login is not required. A user or actor can be selected for demonstration purposes.
- Booking and analytics information should come from the backend.
- The interface should display loading, empty and error states clearly.
- The application should work on laptop screens and remain reasonably usable on mobile devices.
